### 1.2 Socket API in C (POSIX)

**Key functions you must understand and practice:**

| Function | Header | Purpose | Notes |
|----------|--------|---------|-------|
| `socket()` | `<sys/socket.h>` | Create a socket file descriptor | Returns int (fd), or -1 on error; specify AF_INET, SOCK_STREAM, IPPROTO_TCP |
| `bind()` | `<sys/socket.h>` | Attach socket to a port on your machine | Server only; bind to INADDR_ANY (all interfaces) or specific IP |
| `listen()` | `<sys/socket.h>` | Mark socket as accepting connections | Server only; backlog parameter (queue size) |
| `accept()` | `<sys/socket.h>` | Accept incoming connection | Server only; blocks until client connects; returns new fd |
| `connect()` | `<sys/socket.h>` | Initiate connection to server | Client only; provide server address/port; blocks until connected |
| `send()` | `<sys/socket.h>` | Send data over socket | Returns bytes sent (may be < requested); -1 on error |
| `recv()` | `<sys/socket.h>` | Receive data from socket | Returns bytes received (0 = connection closed); blocks until data arrives |
| `close()` | `<unistd.h>` | Close socket file descriptor | Clean shutdown |
| `inet_aton()` | `<arpa/inet.h>` | Convert "192.168.1.1" string to binary | Deprecated but simple; prefer `inet_pton()` |
| `inet_pton()` | `<arpa/inet.h>` | Convert IP address string to binary (IPv4/IPv6) | Modern version of inet_aton |
| `htons()`, `ntohs()` | `<arpa/inet.h>` | Host-to-network byte order (endianness conversion) | Ports must be in network byte order (big-endian) |
| `getaddrinfo()` | `<netdb.h>` | Modern way to resolve hostnames and get socket addresses | More complex but handles IPv4/IPv6; returns struct addrinfo |
| `perror()` or `strerror()` | `<stdio.h>` / `<string.h>` | Print error messages | Use after checking return value == -1 |

**Data structures you'll use:**

```c
// IPv4 socket address (you'll fill this in)
struct sockaddr_in {
    sa_family_t sin_family;      // AF_INET
    in_port_t sin_port;          // Port number (network byte order!)
    struct in_addr sin_addr;     // IP address (network byte order)
    char sin_zero[8];            // Padding; memset to 0
};

struct in_addr {
    uint32_t s_addr;             // IP address as 32-bit number
};

// Generic socket address (used by bind, connect, etc.)
struct sockaddr {
    sa_family_t sa_family;       // AF_INET, AF_INET6, etc.
    char sa_data[14];            // Address data
};
// You cast (struct sockaddr_in *) to (struct sockaddr *) when calling functions
```

### 1.3 HTTP Protocol Basics

**You need to understand HTTP because your frontend/backend will communicate via HTTP.**

**HTTP Request Structure** (what client sends):

```
GET /api/search?query=dune HTTP/1.1
Host: 192.168.1.100:8888
Connection: close
User-Agent: MyMediaApp/1.0
Content-Length: 0

```

**Breaking this down:**
- Line 1: `METHOD PATH PROTOCOL_VERSION` (GET, POST, PUT, DELETE, etc.)
- Headers: Key-Value pairs (Host, Content-Length, User-Agent, etc.)
- Blank line
- Body: (optional, usually for POST/PUT; GET has no body)

**HTTP Response Structure** (what server sends):

```
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 42
Connection: close

[{"title":"Dune","id":123}]
```

**Breaking this down:**
- Line 1: `PROTOCOL_VERSION STATUS_CODE STATUS_MESSAGE` (e.g., "HTTP/1.1 200 OK")
- Headers: Key-Value pairs (Content-Type, Content-Length, etc.)
- Blank line
- Body: Data (JSON, HTML, binary, etc.)

**Common status codes:**
- 200 OK: Success
- 400 Bad Request: Client error (malformed request)
- 404 Not Found: Resource doesn't exist
- 500 Internal Server Error: Server error

**Content-Type header matters:**
- `application/json`: Body is JSON
- `text/plain`: Body is plain text
- `text/html`: Body is HTML
- `video/mp4`: Body is video data
- `application/octet-stream`: Raw binary data

**Learning resources:**
- RFC 7230 (HTTP/1.1 specification) — dense but authoritative
- MDN Web Docs: "HTTP" overview (easier read)
- Beej's Guide, Chapter 6 (has a brief HTTP section)

### 1.4 Handling Multiple Connections (Concurrent I/O)

**Problem**: Your current echo server handles one client, then waits for another. Real servers handle multiple simultaneous clients. There are several approaches:

| Approach | Pros | Cons | Use Case |
|----------|------|------|----------|
| **Threads** (pthreads) | Simple; each client = one thread | Can be expensive (many threads = overhead); synchronization complexity | Good for low-client count (10-100 clients) |
| **Processes** (fork) | Isolation between clients | Very expensive; many processes use lots of RAM | OK for very low concurrency |
| **select()/poll()** | Single-threaded; handle many clients | More complex event loop logic; manual state tracking | Good for high concurrency (1000+ clients) |
| **epoll()** (Linux) | Single-threaded; very efficient | Linux-only; higher complexity | Best for Linux servers with many clients |

**For your RP-NAS backend**: Start with **threads** (easiest to learn). Your home network won't have 1000s of concurrent clients.

**Learning pthreads:**

| Function | Purpose |
|----------|---------|
| `pthread_create()` | Create a new thread |
| `pthread_join()` | Wait for thread to finish |
| `pthread_mutex_init()` | Create a mutex (lock) |
| `pthread_mutex_lock()` | Acquire lock (blocks if held) |
| `pthread_mutex_unlock()` | Release lock |
| `pthread_cond_wait()` | Wait for condition variable |
| `pthread_cond_signal()` | Signal waiting thread |

**Learning resources:**
- Beej's Guide, Chapter 9 (pthreads intro)
- Man pages: `man pthread_create`, `man pthread_mutex_init`, etc.
- "POSIX Threads Programming" (free LLNL tutorial)

### 1.5 Error Handling & Robustness

**In C, you must check return values religiously:**

```c
int sock = socket(AF_INET, SOCK_STREAM, IPPROTO_TCP);
if (sock == -1) {
    perror("socket failed");
    exit(EXIT_FAILURE);
}

int res = bind(sock, (struct sockaddr *)&addr, sizeof(addr));
if (res == -1) {
    perror("bind failed");
    close(sock);
    exit(EXIT_FAILURE);
}
```

**Common error scenarios to handle:**
- Connection refused (server not running)
- Connection reset (server crashed mid-transfer)
- Broken pipe (send() when peer closed)
- Timeout (stuck recv() — use SO_RCVTIMEO socket option)
- Partial sends (send() returns < requested bytes; loop to send rest)
- Partial receives (recv() returns < buffer size; loop to get all)

**Socket options to learn:**
- `SO_REUSEADDR`: Avoid "Address already in use" error when restarting server
- `SO_RCVTIMEO` / `SO_SNDTIMEO`: Timeouts on recv/send
- `SO_KEEPALIVE`: Detect dead connections

```c
int reuse = 1;
setsockopt(sock, SOL_SOCKET, SO_REUSEADDR, &reuse, sizeof(reuse));
```

### 2.1 HTTP Server in C (No External Framework)

**Goal**: Hand-write an HTTP server that can parse requests and send responses. This is educational and gives you control.

**Core workflow for each client connection:**

```
1. accept() connection
2. recv() raw HTTP request bytes into buffer
3. Parse HTTP request:
   - Extract method (GET, POST, etc.)
```
